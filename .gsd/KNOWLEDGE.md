| K001 | backend | GSD doesn't support `--no-themes` flag | Gsd spawn args must NOT include `--no-themes`. Pi spawn args include `--mode rpc --no-themes`. Gsd only uses `--mode rpc`. Including `--no-themes` with gsd will cause spawn failure. | S02/T03 |
| K002 | backend | GSD uses cwd-scoped sessions | Pi sessions: `~/.pi/agent/sessions/` (flat directory). Gsd sessions: `~/.gsd/sessions/<cwd-hash>/` (cwd-scoped subdirectory). Cwd hash format: `--path-with-dashes-replace-by-dashes--` (e.g., `/Users/jim/code/myproject` → `--Users-jim-code-myproject--`). Session listing for gsd MUST pass cwd parameter. | S02/T03 |
| K003 | backend | GSD agent directory structure | Gsd uses `~/.gsd` directly as agent dir (no 'agent' subdirectory). Pi uses `~/.pi/agent` as agent dir. This affects: settings path (gsd: `~/.gsd/settings.json`, pi: `~/.pi/agent/settings.json`), prompts dir, extensions dir, skills dirs. | S02/T01 |
| K004 | backend | GSD quiet startup always true | Gsd backend always has `quietStartup=true` (no startup info emission). Pi backend reads from settings.json. This is a behavioral difference, not a config file setting for gsd. | S02/T03 |
| K005 | backend | Skills directories differ between backends | Gsd skills: `~/.gsd/skills` (global) + `<cwd>/.gsd/skills` (project). Pi skills: `~/.pi/agent/skills` (global) + `~/.agents/skills` (legacy discovery) + `<cwd>/.pi/skills` (project). The legacy `~/.agents/skills` path is pi-specific for backward compatibility with older skill installations. | S02/T01 |
| K006 | backend | Environment variable override precedence | Both backends use `PI_ACP_PI_COMMAND` env var for command override (not backend-specific env vars). Backend inferred from command string (contains "gsd" → gsd backend, otherwise pi). Agent directory override uses backend-specific env vars: `GSD_AGENT_DIR` for gsd, `PI_CODING_AGENT_DIR` for pi. | S02/T01 |
| K007 | backend | Session map path differs | Gsd: `~/.gsd/session-map.json` (directly in agent dir). Pi: `~/.pi/pi-acp/session-map.json` (in pi-acp subdirectory). The pi-acp subdirectory is legacy from the original pi-acp package naming. | S02/T01 |
| K008 | backend | Auto-detection order | Auto-detection tries `gsd` first, then `pi` fallback. Uses `which` (macOS/Linux) or `where` (Windows) to check command availability. If gsd is available, it's the default backend. Override with `PI_ACP_PI_COMMAND=pi` to force pi backend. | S02/T01 |
| K009 | pattern | Getter function for env-configurable constants (D004) | Use getter functions (e.g., `getRpcTimeoutMs()`, `getMaxQueueDepth()`) instead of const for env-configurable values. Node.js module imports are cached, so const values are fixed at load time. Getter functions read env var on each call, enabling runtime override in tests. | S01/T02, S03/T02 |
| K010 | pattern | Timeout wrapper with settled guard (D003) | RPC timeout pattern: use `settled` boolean guard + wrapper functions (`doResolve`/`doReject`) to prevent double-resolve between timeout and process exit. Clear timer in all resolution paths. Pending request cleanup on timeout. | S01/T02 |
| K011 | pattern | Direct instance capture for disposal | Avoid SDK internal property access like `(agent as any)?.agent?.dispose?.()`. Capture the instance before passing to wrapper: `const acpAgent = new PiAcpAgent(conn); const agent = new AgentSideConnection(() => acpAgent, stream);`. Then call `acpAgent.dispose()` directly. | S01/T03 |
| K012 | security | Path validation for user-provided paths | Check absolute path + no traversal (`..`), NOT "within home directory". Allows `/tmp` paths for testing while preventing directory escape attacks. Original "within homedir" validation blocked legitimate test paths. | S01/T01 |
| K013 | testing | Behavioral verification for unmockable internals | When Node.js modules have non-configurable properties (like readline interface), cannot mock internal state. Verify behavior by checking observable effects: e.g., verify `readline.close()` effect by checking stdout data NOT processed after `dispose()`. | S03/T04 |
| K014 | pattern | Zod parsing for RPC responses (D008) | Replace `as any` casts with Zod parsing: `parseState(await proc.getState())`. All schema fields defined as optional for forward compatibility with pi/gsd evolution. `CommandsSchema` supports both string arrays and object arrays (actual pi RPC format). | S04/T01 |
| K015 | pattern | Fire-and-forget async logging | Wrap `fs.appendFile` in `.catch(() => {})` so logging never throws to caller. Debug logging should be opt-in via env var (PI_ACP_DEBUG_LOG). Use ISO timestamps for traceability. | S01/T01 |
| K016 | testing | FakeChildProcess for subprocess mocking | Implement `ChildProcessWithoutNullStreams` interface with EventEmitter-based streams. Provide `simulateSpawn`, `simulateExit`, `simulateError` methods for test control. `stdinWrites` array captures writes for assertions. Avoids real subprocess spawns in tests. | S03/T02 |
| K017 | architecture | Module extraction pattern | Extract focused modules with single responsibility: `builtin-commands.ts` (56 lines), `pkg-utils.ts` (24 lines), `model-utils.ts` (137 lines), `startup-info.ts` (196 lines), `slash-command-dispatcher.ts` (515 lines). Clear imports/exports, tested via integration or dedicated unit tests. | S04/T03-T06 |
| K018 | pattern | Dependency injection for SessionStore | Pass single SessionStore instance to SessionManager constructor instead of dual instantiation. Constructor accepts optional `store?: SessionStore` param, falls back to new instance for backward compat. Prevents race conditions on same file. | S04/T02 |
